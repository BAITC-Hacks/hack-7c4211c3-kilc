# TaskLab — задачи бизнеса для студенческих команд

Хакатонный MVP команды KILC: площадка, где бизнес описывает задачу, оценивает полноту требований и публикует карточку, а студенческие команды предлагают решение. Представитель бизнеса сравнивает предложения, самостоятельно выбирает исполнителей и подтверждает выполненный этап.

Проект помогает бизнесу подготовить понятное задание, а командам — найти задачи с описанием результата, данных, ограничений и критериев успеха. Рейтинг отражает полноту и формальную конкретность описания, а не сложность задачи или качество будущего решения.

> Текущее состояние: каталог, команды, отклики и решения бизнеса подключены к SQLite. AI-пакет реализован отдельно, но не подключён к HTTP-маршрутам. Сохранение из браузерного конструктора имеет известную несовместимость с API; для воспроизводимой проверки создания задачи ниже приведён запрос PowerShell.

## Что реализовано

- Открытый каталог опубликованных задач с сортировкой по убыванию рейтинга и фильтрами по категории, отрасли и уровню готовности.
- Карточка задачи с исходным описанием, контекстом, потребностью, пользователями, данными, ограничениями, ожидаемым результатом, критериями успеха, контактом и форматом взаимодействия.
- Создание, чтение, обновление и публикация задач через JSON API. Исходный черновик после сохранения изменить нельзя.
- Браузерный конструктор: ручное заполнение, подтверждение полей, пересчёт рейтинга на сервере, подсказки и локальная резервная копия новой задачи. Ограничение сохранения описано ниже.
- Рейтинг 0–100 с разбивкой, потенциальным баллом и подсказками. При редактировании поля в конструкторе его подтверждение снимается.
- Просмотр, поиск, создание и выбор команды; профиль содержит название, интересы, навыки и технологии.
- Предложения команд: идея, план, дата завершения и ссылка на прототип. Новое предложение получает статус `pending`.
- Кабинет бизнеса: фильтр по компании, сравнение откликов, ручное принятие или отклонение. Можно принять несколько предложений.
- Однократное подтверждение этапа принятого предложения с начислением 1–100 баллов. Баллы команды вычисляются как сумма начислений.
- Рекомендации: до пяти опубликованных задач по совпадению категории с интересами команды, с рейтингом от 40. Это алгоритм по правилам, без AI; остальные опубликованные задачи остаются в общем каталоге.
- Автоматическое заполнение демонстрационной базы и endpoint проверки состояния `/health`.

### Как считается рейтинг

Баллы начисляются только за заполненные и подтверждённые поля.

| Компонент | Максимум |
|---|---:|
| Контекст и потребность | 20 |
| Данные и материалы | 20 |
| Ожидаемый результат | 15 |
| Критерии успеха | 15 |
| Ограничения | 10 |
| Пользователи | 10 |
| Связь с бизнесом | 10 |
| **Всего** | **100** |

Контекст и потребность дают до 10 баллов каждый; контакт и формат взаимодействия — до 5. Для обычных текстовых полей описание короче пяти слов получает половину максимума с округлением вниз. Для полного балла критерии успеха должны содержать число, контакт — символ `@` или хотя бы семь цифр.

Уровни: **0–39 — черновик**, **40–69 — рабочая**, **70–89 — готовая**, **90–100 — приоритетная**. Уровень вычисляется из балла. Категория на него не влияет. Низкий рейтинг не запрещает публикацию и отправку предложения; для публикации нужны название и подтверждение заполненных полей рейтинга. Статус публикации и уровень «черновик» — разные свойства.

## Как работает решение

1. Бизнес выбирает роль и описывает исходную задачу.
2. Представитель вручную заполняет структурированные поля и подтверждает сведения. Сервер рассчитывает рейтинг и показывает, что нужно дополнить.
3. Задача сохраняется и публикуется отдельным действием. В текущей версии для этого можно использовать API; ограничение конструктора указано в разделе «Ограничения».
4. Команда выбирает задачу в каталоге и отправляет идею, план, срок и ссылку на прототип.
5. Бизнес сравнивает отклики и вручную принимает или отклоняет каждый.
6. После выполнения этапа бизнес подтверждает его и назначает баллы. Они отображаются в профиле команды.

Выбор роли и команды — настройка демонстрационного интерфейса, а не вход в защищённый аккаунт.

## Технологии и AI

| Область | Реализация |
|---|---|
| Сервер | Go 1.25.0 по `go.mod`, стандартный `net/http` |
| HTML | `html/template` для каталога; отдельные HTML-страницы для остальных сценариев |
| Клиент | HTML, CSS, обычный JavaScript и Fetch API; без Node.js и сборки |
| Хранилище | SQLite, `database/sql`, `modernc.org/sqlite v1.59.0` — драйвер без CGO |
| Встраивание ресурсов | `embed.FS`: шаблоны, статика, схема и JSON-данные |
| Тесты | Go `testing`, HTTP-тесты и тесты хранилища |
| Опциональный AI | HTTP-клиент совместимого Chat Completions API; по умолчанию DeepSeek `deepseek-chat` |

Единственная прямая сторонняя Go-зависимость — SQLite-драйвер; его транзитивные зависимости перечислены в `go.mod`. Веб-фреймворка, ORM и JS-зависимостей нет.

Пакет `ai/` предоставляет один интерфейс с двумя операциями:

1. Исходное описание → уточняющие вопросы.
2. Описание и ответы → структурированная карточка.

Есть локальная заглушка, проверка ответа и переход на заглушку с записью в лог при ошибке модели или некорректном ответе. Лишние ключи ответа отбрасываются. Вызовы `ai.New()` и операций интерфейса отсутствуют в текущем серверном сценарии: запуск приложения **не вызывает модель**, а установка AI-переменных сама по себе не включает генерацию в интерфейсе.

## Архитектура

```text
Браузер
  ├─ GET / → HTML-каталог из templates/
  └─ static/task-builder/ → JavaScript → JSON API
                                      ├─ rating/ → оценка без БД и HTTP
                                      └─ store/ → SQLite

main.go → открытие БД → схема → демонстрационные данные → HTTP-сервер
ai/     → отдельный интерфейс, заглушка и клиент модели
          (пока не связан с HTTP-сценарием)
```

| Путь | Назначение |
|---|---|
| `main.go` | Встраивание ресурсов, запуск БД, регистрация маршрутов, health-check |
| `api/` | Каталог, задачи, рейтинг, команды, предложения, действия бизнеса, рекомендации |
| `rating/` | Чистые функции оценки, уровни и расчёт бонуса вознаграждения |
| `store/` | SQL-запросы, валидация, сохранение и загрузка демонстрационных данных |
| `ai/` | Интерфейс из двух операций, заглушка, HTTP-клиент и проверка ответов |
| `templates/` | Серверные HTML-шаблоны |
| `static/` | CSS, JavaScript и страницы конструктора, команд и кабинета бизнеса |
| `schema.sql` | Схема таблиц задач, команд и предложений |
| `data/*.json` | Демонстрационные задачи, команды и предложения |

Рейтинг пересчитывается при сохранении задачи, числовой результат хранится для сортировки. Данные сохраняются между перезапусками в SQLite. Каталог отдаёт только опубликованные задачи.

## Установка и запуск

Потребуются Git, Go **1.25+** и браузер. При первой загрузке зависимостей нужен интернет. API-ключ, отдельный сервер БД и C-компилятор не требуются.

1. Клонируйте репозиторий и перейдите в него:

   ```sh
   git clone https://github.com/BAITC-Hacks/hack-7c4211c3-kilc.git
   cd hack-7c4211c3-kilc
   ```

2. Проверьте Go и загрузите зависимости:

   ```sh
   go version
   go mod download
   ```

3. Запустите сервер:

   ```sh
   go run .
   ```

4. Откройте [каталог](http://localhost:8080/) или [выбор роли](http://localhost:8080/static/task-builder/login.html).

При запуске применяется встроенная схема. Если таблица задач пуста, загружаются **5 черновиков, 5 опубликованных карточек, 5 команд и 5 предложений**. Если задачи уже есть, загрузка пропускается.

HTML следует открывать через Go-сервер: рабочие операции требуют его API. После изменения встроенных HTML/CSS/JS сервер нужно перезапустить.

### Настройки

| Переменная | Значение по умолчанию | Назначение |
|---|---|---|
| `PORT` | `8080` | Порт HTTP-сервера |
| `DB_PATH` | `data.db` | Путь к SQLite относительно рабочей директории |
| `STUB` | Режим заглушки | В `ai.New()` модель выбирается только при `STUB=0` и непустом ключе |
| `AI_API_KEY` | Пусто | Ключ опционального AI-провайдера |
| `AI_BASE_URL` | `https://api.deepseek.com` | Базовый адрес; клиент добавляет `/chat/completions` |
| `AI_MODEL` | `deepseek-chat` | Имя модели |

Последние четыре настройки относятся к отдельному AI-пакету, пока не подключённому к серверу. Файл `.env` автоматически не читается.

Пример отдельной демонстрационной базы в PowerShell:

```powershell
$env:DB_PATH = 'jury-demo.db'
$env:PORT = '8080'
go run .
```

Используйте новое имя базы, если нужно повторно получить исходные примеры, сохранив предыдущие результаты.

## Как проверить решение

### Техническая проверка

Из корня репозитория:

```sh
go test ./rating/...
go run .
```

Во втором терминале:

```sh
curl -f http://localhost:8080/health
```

Ожидаемый ответ — HTTP 200 и `{"status":"ok"}`. В Windows PowerShell можно вызвать `curl.exe -f http://localhost:8080/health`.

Для проверки всех пакетов:

```sh
go test ./...
```

### Сценарий для жюри

1. Запустите сервер с новой демонстрационной базой и откройте каталог. Проверьте карточки, их рейтинг и фильтры.
2. На странице выбора роли выберите студенческую команду. Откройте список команд, выберите существующую и перейдите к задачам.
3. Откройте опубликованную карточку. Заполните предложение: идея — «Собрать единый список заявок», план — «Изучить данные, сделать прототип, провести проверку», срок — `2026-12-31`, ссылка — `https://example.com/jury-demo`. Это демонстрационная ссылка, не готовый прототип.
4. Отправьте предложение. Интерфейс должен сообщить, что решение принимает бизнес; число откликов увеличится.
5. Откройте [кабинет бизнеса](http://localhost:8080/static/task-builder/business.html), найдите задачу и нажмите «Сравнить отклики». Примите созданное предложение.
6. Подтвердите этап, указав 10 баллов. Обновите страницу команд: сумма баллов выбранной команды должна увеличиться на 10. Повторное начисление за тот же этап недоступно.
7. Для проверки рейтинга откройте [конструктор](http://localhost:8080/static/task-builder/). Введите контекст «Менеджеры вручную переносят заявки из почты в таблицу», подтвердите поле и посмотрите разбивку. Измените текст: подтверждение снимется, вклад поля в подтверждённый рейтинг исчезнет. Сохранение из этой формы пока ограничено описанной ниже ошибкой.

### Создание и публикация через API

Следующий пример выполняется в PowerShell при работающем сервере. Он создаёт задачу с рейтингом **10/100** и публикует её — это также проверка доступности каталога для задач с низкой оценкой.

```powershell
$base = 'http://localhost:8080'
$payload = @{
    company = 'Демо для жюри'
    title = 'Единый список заявок'
    industry = 'Услуги'
    category = 'automation'
    draft_text = 'Нужно собрать заявки из почты в единый список.'
    context = 'Менеджеры вручную переносят заявки из почты в таблицу'
    confirmed = @('context')
} | ConvertTo-Json -Depth 4

$task = Invoke-RestMethod -Method Post -Uri "$base/api/tasks" `
    -ContentType 'application/json; charset=utf-8' `
    -Body ([System.Text.Encoding]::UTF8.GetBytes($payload))

$published = Invoke-RestMethod -Method Post `
    -Uri "$base/api/tasks/$($task.id)/publish" `
    -ContentType 'application/json' -Body '{}'

$published | ConvertTo-Json -Depth 8
```

Ожидаемые значения: `status: published`, `rating.total: 10`, `rating.level: draft`. Найдите новую карточку в каталоге: на неё тоже можно отправить предложение.

## Данные и интеграции

- Источник начальных данных — `data/tasks.json`, `data/teams.json` и `data/proposals.json`. Это демонстрационные примеры, а не подтверждённые реальные заказчики или результаты проектов.
- Пользовательские задачи, профили команд и предложения сохраняются в SQLite. Файлы и прототипы не загружаются: предложение хранит только URL.
- Профили команд содержат общие навыки и технологии, без сведений об отдельных участниках.
- Выбор роли, компании и команды хранится в `sessionStorage`; резервная копия новой задачи — в `localStorage`.
- Внешний AI API предусмотрен в `ai/`, но текущий пользовательский сценарий работает без него. Интеграций с CRM, мессенджерами и внешними источниками бизнес-данных нет.
- Ссылки `example.com` в начальных предложениях — демонстрационные адреса.

## Ограничения текущей версии

- **Сохранение из конструктора:** `static/task-builder/app.js` отправляет `reward` и `reward_type`, но `api/frontend.go` не включает их в тело задачи и запрещает неизвестные поля. Поэтому сохранение и публикация через форму получают HTTP 400 даже при пустом вознаграждении. Используйте приведённый выше API-пример без этих полей.
- **Бонус вознаграждения реализован частично:** расчёт доступен в рейтинге и интерфейсе, но поля не сохраняются в таблице задач; реальный каталог сортируется по `score`, без бонуса.
- **AI не подключён к интерфейсу и маршрутам сервера:** автоматическое уточнение и генерация карточки не являются доступным сквозным пользовательским сценарием.
- Нет аутентификации и разграничения доступа. Выбор роли не защищает действия бизнеса; API не проверяет владельца задачи или участника команды.
- Оценка использует простые текстовые правила; она не проверяет достоверность данных, реализуемость задания и качество решения.
- Нет чата, уведомлений, загрузки файлов, управления участниками команды и полноценного трекера проекта.
- Подтверждается один этап на предложение; повторное начисление и пересмотр уже принятого решения не предусмотрены.
- Репозиторий не содержит конфигурации промышленного развёртывания. Текущая версия предназначена для демонстрации MVP.
