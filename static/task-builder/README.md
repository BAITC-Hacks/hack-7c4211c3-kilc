# TaskLab: страницы, подключённые к Go и SQLite

## Запуск

Из корня репозитория выполните `go run .` (нужен Go 1.25+), затем откройте http://localhost:8080.
Страницы и ресурсы встроены в Go через embed.FS. После изменения HTML/JS/CSS перезапустите сервер.
Открытие HTML двойным щелчком или через отдельный статический сервер больше не поддерживает рабочие операции: нужен API того же Go-сервера.

## Страницы

- `/static/task-builder/login.html` — выбор роли бизнеса или студенческой команды.
- `/static/task-builder/teams.html` — команды из SQLite, поиск, фильтр по интересам, создание и выбор команды.
- `/static/task-builder/` — конструктор задачи; `?id=123` открывает сохранённую задачу.

## Поведение

Конструктор использует имена полей из store.Task. Категории загружаются из серверного справочника.
Каждое поле рейтинга имеет подтверждение. Редактирование снимает подтверждение только с изменённого поля.
Рейтинг и потенциальный балл рассчитываются только в Go; клиент показывает components и hints из ответа.
Сохранение создаёт или обновляет задачу в SQLite. Публикация выполняется отдельным явным действием.
Исходный draft_text нельзя менять после первого сохранения. Низкий рейтинг не запрещает публикацию.
Новая несохранённая задача имеет локальную резервную копию; сохранённые задачи загружаются из базы по ID.

Команда хранит name, interests (коды категорий), skills и tech. Баллы выдаёт сервер, исходя из подтверждённых этапов предложений.
Выбранный ID команды сохраняется только в sessionStorage и доступен через событие `team:selected` с командой в event.detail.
Это выбор роли MVP, а не членство или авторизация. В актуальной схеме нет пользовательских аккаунтов, участников, кодов приглашения и лимитов состава. Демо-механика localStorage из предыдущей версии удалена.
Данные старого локального демо автоматически не импортируются. Страница `task.html?id=123` показывает задачу и форму отклика; `business.html` — кабинет бизнеса.

## AI-помощник

Введите исходное описание, нажмите «Получить уточняющие вопросы», заполните
ответы и нажмите «Сформировать карточку». Неизвестные ответы можно оставить
пустыми. Помощник заменяет название, категорию и девять полей описания только
после явного действия пользователя; если эти поля уже заполнены, форма
предупреждает о замене. Компания, отрасль, исходный черновик и вознаграждение
сохраняются. Все предложенные поля остаются неподтверждёнными.

Вопросы и ответы сохраняются в `qa` при обычном сохранении задачи. Для новой
задачи они также входят в локальную резервную копию; смена исходного описания
сбрасывает вопросы. AI-запросы сами не создают и не публикуют задачи.

По умолчанию используется заглушка: API-ключ не нужен. Она переносит только
исходный текст и ответы пользователя. Для модели задайте `STUB=0` и
`AI_API_KEY` при запуске сервера; необязательные `AI_BASE_URL` и `AI_MODEL`
переопределяют настройки клиента (по умолчанию DeepSeek / `deepseek-chat`).
Ключ используется только на сервере. Ошибка или некорректный ответ модели
приводят к заглушке с записью в серверный лог; UI показывает источник результата.
Ответы и ранее заполненная карточка остаются в форме при ошибке запроса.

Интеграционные зависимости: задачи в `BACKEND_TASKS.md` добавляют сохранение
вознаграждения и серверную поддержку подтверждений `title`/`category`.
До их выполнения генерация работает, но сохранение полного payload текущего
конструктора блокируется строгим API. Проверки API генерации не заменяют
проверку сохранения и публикации через браузер после этих исправлений.

## API

- GET /api/categories
- POST /api/ai/questions: {draft_text} → {questions: [{field, question}], source}
- POST /api/ai/card: {draft_text, qa: [{field, question, answer}]} → {card, source}
- GET /api/teams; POST /api/teams: {name, interests, skills, tech}
- POST /api/rating: поля rating.Card как {text, confirmed}, только 9 полей рейтинга
- GET /api/tasks?category=&industry=&level=: опубликованный каталог
- POST /api/tasks: поля задачи, qa и confirmed; без ID, status и rating
- GET /api/tasks/{id}; PUT /api/tasks/{id}
- POST /api/tasks/{id}/publish: {}

Ответ задачи: поля задачи + id, status и rating {total, potential, level, level_label, components, hints}.
Ошибки: JSON {error: string}, соответствующий HTTP-статус. Запросы записи требуют Content-Type application/json, максимум 64 КБ.
AI принимает непустой черновик до 4000 символов и 3–5 разных допустимых полей
в `qa`; текст каждого вопроса и ответа — до 2000 символов. Ответ может быть
пустым. Успех — 200, неверные данные — 400, слишком большой запрос — 413,
неверный Content-Type — 415, ошибка клиента AI без успешного fallback — 502.
`source` имеет значение `stub` или `model`.
Маршруты зарегистрированы в api/frontend.go, api/ai.go и main.go. Хранилище и формула рейтинга используются без дублирования в JS.

## Проверка

`go test ./...` проверяет рейтинг, хранилище и API, включая создание команд, сохранение и публикацию задач, валидацию категорий и неизменность исходного черновика.
После запуска: GET /health должен вернуть {"status":"ok"}.
В браузере проверены публикация задачи с 10 баллами, повторная загрузка по ID, снятие подтверждения при редактировании и создание команды в SQLite.
