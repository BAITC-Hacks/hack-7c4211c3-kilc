# Настройка окружения и проверка AI

Из корня репозитория запускайте `go run .`: сервер автоматически читает
локальный `.env` до открытия базы и создания AI-клиента. Файл необязателен.
Переменные окружения процесса имеют приоритет, даже если значение пустое.
Команда `source .env` не требуется.

Пример `.env` для OpenAI (вставьте свой ключ локально):

```dotenv
STUB=0
AI_API_KEY=your-api-key
AI_BASE_URL=https://api.openai.com/v1
AI_MODEL=gpt-4.1-mini
PORT=8080
DB_PATH=data.db
```

Используется имя `AI_API_KEY`. Для OpenAI задайте также `AI_BASE_URL` и
`AI_MODEL`: без этих переопределений клиент использует настройки DeepSeek.
Без ключа или при `STUB`, отличном от `0`, работает заглушка. Для явного
запуска без внешних AI-запросов: `STUB=1 go run .`.

Поддерживаются `KEY=value`, необязательный `export`, одинарные/двойные
кавычки и комментарии `#`. В некавыченном значении комментарий начинается
после пробела. Значения однострочные; внутри двойных кавычек поддерживаются
`\n`, `\t`, `\r`, `\\` и `\"`. Подстановка `$VARIABLE` и запуск shell-команд
не выполняются. Ошибка формата останавливает запуск с номером строки без
вывода значения. После изменения `.env` перезапустите сервер. Локальные
env-файлы исключены из Git; не добавляйте ключи в код или коммиты.

## Проверка ответа

AI формирует 3–5 вопросов, затем карточку из исходного описания и ответов.
Текстовые поля принимаются только как целые предложения/строки из этих
источников: свободный пересказ и неподтверждённые фразы отбрасываются.
Проверка допускает различия в регистре, пробелах и завершающей точке,
но не превращение вопроса в утверждение. Текст самих вопросов не считается
источником фактов. Категория допускается только из справочника.

Проверяются типы и длины полей; неизвестные ключи удаляются. Пустая карточка,
карточка только с категорией или ответ без пригодного текста вызывает
fallback на заглушку с записью в лог. Диагностика отброшенных полей не
содержит исходный текст, контакты или неизвестные значения модели.
UI/API показывают источник `model` или `stub`.

Такой режим намеренно ограничивает перефразирование. Извлечение текста
не заменяет проверку смысла владельцем: сгенерированные поля необходимо
подтвердить перед публикацией.

## Проверка локально

```sh
go test ./rating/...
go test ./...
```

Тесты используют временные `.env`-файлы, тестовые ключи и локальные mock-серверы;
реальный API-ключ не требуется. Проверяются приоритет окружения, выбор клиента,
некорректные ответы, выдуманный текст и fallback.

После запуска сервера `curl -f http://localhost:8080/health` должен вернуть
`{"status":"ok"}`. Для пользовательской проверки выберите роль бизнеса,
откройте конструктор и пройдите вопросы → ответы → карточка. Источник `model`
означает успешный ответ модели, `stub` — заглушку; причину fallback смотрите
в серверном логе.
